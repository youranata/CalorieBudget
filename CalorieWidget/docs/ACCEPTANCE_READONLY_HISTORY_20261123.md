# 当天明细与历史只读汇总：变更验收及独立审计

日期：2026-11-23。变更前基线：`e4757bea51a27665488e7b9e501def33ad46ec2f`。应用版本 1.1（versionCode 2），Room 数据库版本 3。

## 当前规则

- 当天保留完整摄入明细，支持 kcal/kJ、新增、修改数值/单位/备注/时间、确认删除及预算设置。
- 过往仅保存日期、当日目标与总摄入，页面只读，不再保存逐笔金额、备注、时间或记录条数。剩余量和 kJ 为已有数值的换算/计算结果。
- 数据库另保留一个“有无记录”标志，用于继续区分无数据和明确的零摄入，不保存明细数量。
- 不允许补录历史、移动记录至历史日期、编辑已归档记录或修改历史目标。归档日期即使因回拨系统日期/时区再次成为今天，也不会重新开放。
- 未知历史日期显示暂无保存数据，不因查询而补造预算和零摄入日。

首次升级会把已有历史明细汇总后删除；当天明细和设置保留。历史明细删除后不能通过应用恢复。本报告规则取代此前报告中的“历史明细永久保留、历史可编辑”行为。

## 实现与一致性

`DailyBudgetEntity` 新增可空的归档总额和有无记录标志。总额非空表示已锁定；已有历史预算快照不重写。当天仍从明细求和，余额不另行存储。

每次日期校验在 Room 事务中依次准备旧明细所缺的预算、冻结目标/总摄入、删除过去日期明细、创建当天预算。归档 UPDATE 只处理未归档日期，重复刷新不会重新汇总为零。任何环节失败，目标/总摄入及明细删除全部回滚。

新增、编辑、删除及预算设置均在 Repository 验证目标日期和归档状态；旧表单、历史记录 ID 或直接调用 Repository 也不能写入历史。历史页隐藏新增入口及明细行；输入页禁止选择其他日期。

数据库支持 1→2→3、2→3 升级。2→3 迁移自身完成历史归档，首次 Repository 读取前旧明细即已移除；新版本 Schema 随工程提交。没有破坏性重建或清库回退。
