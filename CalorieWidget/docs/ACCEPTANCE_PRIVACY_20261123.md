这些信息不在本报告复述。当前文件已脱敏，后续提交已切换为项目通用作者身份。**普通清理提交不会删除旧版本，因此“当前文件已清理”和“整个历史已清理”不能等同。** 截至本次普通提交，远端历史尚未重写，整个仓库的历史隐私验收仍未通过。

审计覆盖 Git 可访问的分支与标签、所有可达提交、文件内容与路径、作者/提交者元数据及 Wrapper JAR 解压内容。远端当时仅公布一个主分支，无标签。GitHub REST API 在当前认证条件下返回 404，未据此推断仓库可见性，也未声称检查了服务器缓存、fork 或不可见附件。

- 新提交使用项目通用身份及保留域占位邮箱，不再沿用个人邮箱。

应用 ID 改变意味着旧开发版不能直接覆盖安装；Android 不会自动将原应用 ID 的本地数据库交给新应用 ID。未对手机或真实用户数据执行迁移、删除或卸载。

未发现已跟踪的 SSH 私钥、签名私钥/keystore、真实数据库、APK、local.properties、设备序列号、IMEI 或已识别的访问令牌。Wrapper JAR 内部也进行了扫描。识别规则扫描不能证明任意未知格式的秘密绝对不存在。

新增可重复扫描脚本：`scripts/audit_privacy.py`。输出只包含分类、计数和脱敏后的文件位置，不打印匹配到的个人信息原值。

```bash

python3 scripts/audit_privacy.py --index   # 提交前检查暂存文件

python3 scripts/audit_privacy.py --history # 检查全部可达历史
```

脚本检查邮件、本机路径、当前本机/远端账号标识、常见密钥与令牌、常见设备标识、手机号及不应跟踪的私有文件。可通过 `--identifiers-file` 提供额外的本地 JSON 标识列表；该列表应保存在被忽略的 `.tools/` 中，不应提交。

## 历史清理

移除旧版本内容及提交元数据需要改写历史，会改变提交 ID，必须通过一次明确的历史替换操作才能覆盖远端主分支。可先在被忽略的本地隔离镜像中准备完整历史副本并扫描验证，保留原始备份；未获确认前不执行远端强制推送。

即使改写可达历史，也不能单凭本地扫描保证 GitHub 或他人克隆中的既有副本已删除。因此本报告不会声称已清除第三方保存的内容。
